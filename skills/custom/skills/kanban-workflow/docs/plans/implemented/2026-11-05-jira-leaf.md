# Jira leaf workflow

## Goal

`/jira-task [KEY] [notes]`: implement one Jira ticket as a kanban-workflow
leaf, end with a Bitbucket PR. No fan-out. Jira read-only; user owns Jira
status. Rerun on a ticket with an open PR pulls unresolved PR comments in as
feedback for a new pass.

## Decisions

- Jira = source. Local kanban-md task = state store (body drives
  `kanban_review.py`, resumability, reviewer spec).
- Board always exists at project root; no init step.
- Always finish with PR; never local `wt merge`.
- Commit subject `KEY: msg` when body has `Ticket: KEY`.
- PRs on Bitbucket via `twg bb prs create`.
- Local task `done` once PR opens (`review` = user reviewing; PR is past it).
- Worktree removed after each push; review JSON state dies with it.
- No Jira writes. Jira dev integration links PR via key in branch/title.
- Replying to / resolving BB comments: user's job.
- Push/rebase details: implementing agent's call.

## Proposed changes

### 1. New `jira-task/SKILL.md` (~70 lines)

`allowed-tools`: `kanban-md`, `git`, `wt`, `twg`, `uv`, `jq`, `awk`, `date`.
`disable-model-invocation: true`.

1. `kanban-md agent-name` → `<agent>`.
2. Pick task:
   - KEY given → `kanban-md list --property jira=KEY --json`.
   - No KEY → list tasks with a `jira` property, newest first
     (`kanban-md list --sort updated -r --json`, filter with `jq`; verify JSON
     shape). Exactly one `in-progress` or with `PR:` line → confirm with user.
     Else show list, user picks.
3. Route:
   - Missing → new task (step 4).
   - Body has `PR:` line → PR feedback (§1b).
   - Else → resume: `kanban-md edit <id> --claim <agent>` (nonzero → STOP,
     quote stderr), read `Base:` and `Branch:` from body,
     `wt switch <branch> --no-cd --format json`, then step 7.
4. New task: fetch ticket
   `twg jira workitem get KEY --fields summary,description,issuetype,subtasks -o json`
   (verify field names on first run; description may be ADF). Subtasks
   present → STOP, report. Create in one call:
   `kanban-md create "<summary>" --set-property jira=KEY --claim <agent> --status in-progress --body …`.
   Body: `Ticket: KEY`, `Base: <parent-branch>`, URL, description, acceptance
   criteria (copied: reviewers never fetch Jira).
5. Plan gate: kanban-workflow `SKILL.md` Step 2. Grilling wants a split →
   STOP; never create children.
6. Base and worktree:
   - `<default>`: `git symbolic-ref refs/remotes/origin/HEAD`, fallback
     `git ls-remote --symref origin HEAD`. `git fetch origin <default>`;
     `<parent-branch>` = `origin/<default>` unless user names one.
   - Branch per `branch-naming.md`. Worktree per kanban-workflow `SKILL.md`
     leaf step 2 (`wt switch --create … --base <parent-branch>`), record
     `Branch:`.
7. Follow `kanban-leaf-task.md`. Extra args (`notes`) → `## User feedback` at
   Entry.
8. Follow `merge-gate.md` with `<finish>` = `pr`.

Reuses by path: `../kanban-workflow/{kanban-leaf-task.md,merge-gate.md,branch-naming.md,kanban_review.py}`.

### 1b. PR feedback section in `jira-task/SKILL.md`

1. Read `PR:`, `Base:`, `Branch:` from body.
2. `twg bb prs comment query <id> -o json`; keep unresolved (verify JSON
   field). Show them; user picks which to act on (default all). None and no
   extra args → STOP.
3. Claim (`--status in-progress`; nonzero → STOP), recreate worktree:
   `wt switch <branch> --no-cd --format json`.
4. Record picked comments plus extra args as one `## User feedback` section:
   per comment author and file:line, text as `> ` quoted lines (a raw `## `
   line would end the section early in `kanban_review.py`).
5. Implement the feedback and commit, then enter `kanban-leaf-task.md`
   Review loop step 1. Skips leaf Entry, which would review the unchanged
   diff first and waste a round.
6. Follow `merge-gate.md` with `<finish>` = `pr` (push branch).

### 2. `kanban-workflow/kanban-leaf-task.md`

Commit rule: body has `Ticket: KEY` → subject `KEY: <msg>`; else
`<msg> (task <task-id>)`. Keep the "never `#N`" warning.

### 3. `kanban-workflow/merge-gate.md`

New param `<finish>`: `merge` (default, existing callers untouched) | `pr`.
Values for `pr`: `KEY` from body `Ticket:`, `<summary>` = task title,
`<dest>` = `<target-branch>` minus `origin/`, `<branch>` from body `Branch:`.

Approved + `pr`:

- Body has no `PR:` line → open PR:
  ```bash
  git -C <worktree-path> push -u origin <branch>
  twg bb prs create --source <branch> --dest <dest> \
    --title "KEY: <summary>" --description-file <file> -o json
  kanban-md edit <task-id> --release --status done -a "PR: <id> <url>" -t
  wt remove --foreground <branch>
  ```
  `<file>`: written to scratchpad; ticket URL, judgment calls, tests run.
  Verify PR id/url fields in output on first run. twg infers workspace/repo
  from the Bitbucket `origin` remote. Merge-gate approval covers the reviewer
  notification.
- `PR:` line present → `git -C <worktree-path> push`, then
  `kanban-md edit <task-id> --release --status done -a "pushed <sha> to PR <id>" -t`,
  `wt remove --foreground <branch>`.

Not-approved and conflict paths unchanged.

### 4. `kanban-workflow/branch-naming.md`

Rule 2: add shape `<KEY>-<slug>` for a leaf with a ticket id.
